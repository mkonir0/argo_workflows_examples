# TESTAUTO Jira Description Requirements

Every ticket must have all required sections for its type, each filled with real content (no empty headings). Rule of thumb: a TA team member should be able to implement it without asking questions.

## Required sections by type

- **Story:** `As / I want / So that`, Background, Acceptance Criteria, Technical Notes (affected components, approach, dependencies)
- **Task:** Objective, Details, Acceptance Criteria, Technical Details (affected files/components, approach, tools)
- **Defect:** Steps to Reproduce, Expected, Actual, Environment
- **Spike:** Research Question, Goals, Timebox

## Must always be clear

- What needs to change
- Which files, components, or test suites are affected
- The technical approach
- Testable acceptance criteria
